#### 🔹 Shobit's DDL Tasks (`sql/shobit_01_schema.sql`):
- [x] **Create `DEPARTMENTS` Table:**
  ```sql
  CREATE TABLE DEPARTMENTS (
      department_id     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      department_name   VARCHAR2(100) NOT NULL,
      location_building VARCHAR2(50)
  );
  ```
  - *Constraints Demonstrated:* `PRIMARY KEY`, `NOT NULL`, `GENERATED BY DEFAULT AS IDENTITY`.
- [x] **Create `EMPLOYEES` Table:**
  ```sql
  CREATE TABLE EMPLOYEES (
      employee_id   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      department_id NUMBER REFERENCES DEPARTMENTS(department_id) ON DELETE SET NULL,
      full_name     VARCHAR2(100) NOT NULL,
      email         VARCHAR2(150) NOT NULL UNIQUE,
      role          VARCHAR2(20)  NOT NULL CHECK (role IN ('USER', 'TECHNICIAN', 'ADMIN'))
  );
  ```
  - *Constraints Demonstrated:* `PRIMARY KEY`, `FOREIGN KEY (ON DELETE SET NULL)`, `UNIQUE`, `NOT NULL`, `CHECK`.

#### 🔹 Arnav's DDL Tasks (`sql/01_schema.sql` & `sql/scratch_ddl_demo.sql`):
- [x] **Create `TICKETS` Table:**
  ```sql
  CREATE TABLE TICKETS (
      ticket_id      NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      user_id        NUMBER NOT NULL REFERENCES EMPLOYEES(employee_id) ON DELETE CASCADE,
      issue_category VARCHAR2(50) NOT NULL,
      priority_level VARCHAR2(20) DEFAULT 'MEDIUM' NOT NULL CHECK (priority_level IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL')),
      status         VARCHAR2(20) DEFAULT 'OPEN' NOT NULL CHECK (status IN ('OPEN', 'IN_PROGRESS', 'RESOLVED', 'CLOSED')),
      created_at     TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL
  );
  ```
  - *Constraints Demonstrated:* `PRIMARY KEY`, `FOREIGN KEY (ON DELETE CASCADE)`, `CHECK`, `DEFAULT`, `NOT NULL`.
- [x] **Create `TICKET_RESOLUTIONS` Table:**
  ```sql
  CREATE TABLE TICKET_RESOLUTIONS (
      resolution_id    NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      ticket_id        NUMBER NOT NULL UNIQUE REFERENCES TICKETS(ticket_id) ON DELETE CASCADE,
      technician_id    NUMBER NOT NULL REFERENCES EMPLOYEES(employee_id),
      resolution_notes VARCHAR2(1000) NOT NULL,
      resolved_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL
  );
  ```
  - *Constraints Demonstrated:* `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE` (enforcing strict 1-to-1 incident resolution), `DEFAULT`, `NOT NULL`.

### 2.1 Subqueries (Correlated & Non-Correlated)

#### 🔹 Shobit's Subqueries:
- [ ] **Non-Correlated Subquery (`IN` / `NOT IN`):**  
  Find all departments that currently have zero assigned technicians:  
  `SELECT department_name FROM DEPARTMENTS WHERE department_id NOT IN (SELECT DISTINCT department_id FROM EMPLOYEES WHERE role = 'TECHNICIAN' AND department_id IS NOT NULL);`
- [ ] **Correlated Subquery with `EXISTS`:**  
  Find employees who have never filed a support ticket:  
  `SELECT e.full_name, e.email FROM EMPLOYEES e WHERE e.role = 'USER' AND NOT EXISTS (SELECT 1 FROM TICKETS t WHERE t.user_id = e.employee_id);`

#### 🔹 Arnav's Subqueries:
- [ ] **Scalar Subquery in `SELECT`:**  
  List each ticket along with the total count of open tickets by that same user:  
  `SELECT t.ticket_id, t.user_id, t.issue_category, (SELECT COUNT(*) FROM TICKETS t2 WHERE t2.user_id = t.user_id AND t2.status = 'OPEN') AS USER_OPEN_TICKET_COUNT FROM TICKETS t;`
- [ ] **Correlated Subquery with Comparison Operator (`>`):**  
  Find tickets that took longer to resolve than the overall average resolution time:  
  `SELECT t.ticket_id, t.issue_category, (CAST(r.resolved_at AS DATE) - CAST(t.created_at AS DATE)) * 24 AS HOURS_TAKEN FROM TICKETS t JOIN TICKET_RESOLUTIONS r ON t.ticket_id = r.ticket_id WHERE (CAST(r.resolved_at AS DATE) - CAST(t.created_at AS DATE)) > (SELECT AVG(CAST(r2.resolved_at AS DATE) - CAST(t2.created_at AS DATE)) FROM TICKETS t2 JOIN TICKET_RESOLUTIONS r2 ON t2.ticket_id = r2.ticket_id);`

### 2.2 Joins (Inner, Outer & Multi-Table Joins)

#### 🔹 Shobit's Joins:
- [ ] **Multi-Table Inner Join:** Join `DEPARTMENTS` $\leftrightarrow$ `EMPLOYEES` to list all staff with their building location.

  `SELECT d.department_name, COUNT(e.employee_id) AS TOTAL_STAFF FROM DEPARTMENTS d LEFT OUTER JOIN EMPLOYEES e ON d.department_id = e.department_id GROUP BY d.department_name;`

### 2.4 PL/SQL Stored Procedures (`sql/05_procedures.sql`)

#### 🔹 Shobit's Stored Procedure:
- [ ] **`PROCEDURE sp_transfer_employee`:**
  - *Parameters:* `p_employee_id IN NUMBER`, `p_new_dept_id IN NUMBER`, `p_status OUT VARCHAR2`.
  - *Logic:* Validates that the target department exists; updates employee's department; rolls back and sets status to `'DEPT_NOT_FOUND'` if invalid; commits and returns `'SUCCESS'`.

#### 🔹 Arnav's Stored Procedure:
- [ ] **`PROCEDURE sp_resolve_ticket`:**
  - *Parameters:* `p_ticket_id IN NUMBER`, `p_technician_id IN NUMBER`, `p_notes IN VARCHAR2`, `p_result OUT VARCHAR2`.
  - *Logic:*
    1. Validates that the ticket exists and has status `'OPEN'` or `'IN_PROGRESS'`.
    2. Validates that `p_technician_id` has `role = 'TECHNICIAN'`.
    3. Atomically inserts into `TICKET_RESOLUTIONS`.
    4. Updates `TICKETS.status = 'RESOLVED'`.
    5. Commits the transaction.
    6. Uses `EXCEPTION WHEN OTHERS THEN ROLLBACK;` with custom error messages.

### 2.7 Database Triggers (`sql/08_triggers.sql`)

#### 🔹 Shobit's Triggers:
- [ ] **`trg_enforce_technician_role` (BEFORE INSERT on `TICKET_RESOLUTIONS`):**  
  Checks that the `technician_id` belongs to an employee with `role = 'TECHNICIAN'`. If a user with `role = 'USER'` is passed, raises `RAISE_APPLICATION_ERROR(-20001, 'Only technicians can resolve tickets.');`.
- [ ] **`trg_lowercase_email` (BEFORE INSERT OR UPDATE on `EMPLOYEES`):**  
  Automatically executes `:NEW.email := LOWER(:NEW.email);` before saving to enforce data cleanliness.

#### 🔹 Arnav's Triggers:
- [ ] **`trg_ticket_audit_log` (AFTER UPDATE OF status ON `TICKETS`):**  
  Creates an audit table `TICKET_AUDIT_LOG`:
  ```sql
  CREATE TABLE TICKET_AUDIT_LOG (
      log_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
      ticket_id NUMBER,
      old_status VARCHAR2(20),
      new_status VARCHAR2(20),
      changed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
  ```
  Row-level trigger automatically logs status transitions (`:OLD.status` $\rightarrow$ `:NEW.status`) with timestamps for every lifecycle update.
- [ ] **`trg_prevent_resolved_ticket_mod` (BEFORE UPDATE ON `TICKETS`):**  
  Prevents changing the category or priority of a ticket once it has reached `'RESOLVED'` or `'CLOSED'` status.
